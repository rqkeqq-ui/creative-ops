# Roadmap

Формат — как просил заказчик: 4 шага, у каждого есть измеримый результат.

## Шаг 1. Research → стек, архитектура, план (≈1 ч)
* Декомпозиция ТЗ на требования F1–F11 (`docs/01-RESEARCH.md`).
* Сравнение 5 fullstack-вариантов, 5 вариантов БД, 4 — UI, 4 — тестов.
* Решения: Next.js 15 + Route Handlers, SQLite через штатный `node:sqlite`, Tailwind v4, Vitest + Playwright.
* Схема слоёв, модель данных, state machine, RBAC, карта API (`docs/02-ARCHITECTURE.md`).
* **Результат:** документы + список рисков с митигациями.

## Шаг 2. Тесты под задачи (≈3 ч)
Пишем тесты раньше кода, по каждому пункту ТЗ:

| Требование | Тест |
|---|---|
| F1 роли | `tests/integration/rbac.test.ts` (403 на каждое запрещённое действие) |
| F2 форма ТЗ | `tests/integration/tasks.test.ts` + `tests/unit/validation.test.ts` (граничные значения) |
| F3 Kanban | `tests/unit/transitions.test.ts` (полная матрица 5×4), `tests/integration/lifecycle.test.ts` |
| F4 взять/сдать/принять/правки | `tests/integration/lifecycle.test.ts`, E2E `lifecycle.spec.ts` |
| F5 время | `tests/unit/time.test.ts` (длительности, просрочка), проверка таймстемпов в интеграции |
| F6 AI-расходы | `tests/integration/ai-usage.test.ts` (фазы, агрегаты, запрет для байера) |
| F7 аналитика | `tests/unit/analytics.test.ts` + `tests/integration/analytics.test.ts` (сверка цифр на фикстурах) |
| F8 история | `tests/integration/activity.test.ts` (полный аудит, порядок, неизменяемость) |
| F9 демо-данные | `tests/integration/seed.test.ts` (все статусы, все роли, ненулевая аналитика) |
| F10/F11 | `e2e` сценарии + smoke на `/api/meta` |

**Результат:** прогон `npm test` — все тесты красные (кода ещё нет), отчёт сохранён как доказательство TDD-подхода.

## Шаг 3. Код под тесты (≈8 ч)
Порядок: схема БД → домен → сервисы → API → UI (Kanban, форма, карточка, аналитика, вход).
Правило: если тест не проходит — правим код, а не тест. Ослабление теста допускается только при доказанной ошибке в самом тесте, с пометкой в commit message.
Промежуточные приёмки: `npm run test:unit` → `test:integration` → `test:api` → `test:e2e` → `npm run build`.

## Шаг 4. Демо-продукт (≈4 ч)
* Автосев при старте (пустая БД наполняется демо-данными), демо-аккаунты на странице входа.
* Скриншоты ключевых экранов, запись трасс Playwright.
* README: запуск за 3 команды, демо-доступы, что реализовано и что осознанно вне скоупа.
* GitHub-репозиторий, `docs/05-AI-USAGE.md` — какие AI-инструменты и как использовались, включая организацию мультиагентной работы.
* Публичный URL: Dockerfile + `render.yaml` + инструкция; локальный запуск и туннель — если у владельца нет кредов хостинга.

## Что дальше после прототипа (через этап доработки)
1. Postgres + миграции (интерфейс `Db` уже изолирует драйвер).
2. Загрузка файлов (S3-совместимое хранилище) и превью креативов.
3. Realtime (SSE/WebSocket) и уведомления в Telegram.
4. SLA-эскалации, WIP-лимиты, автоподбор исполнителя по загрузке.
5. Экспорт отчётов (XLSX/PDF), ставки и расчёт стоимости часа.
6. Аудит-экспорт и тонкие права (команды/отделы).
